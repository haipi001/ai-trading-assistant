# r127 T0：报价时效及部分成交剩余估值

本轮继续完整工程包目标。当前增量未改变UI、生产配置或真实资产，未提交推送。T0仍在进行。

## 实现

- ExecutionGate始终要求当前资产的服务端报价，不再接受latest_quote_required=false关闭检查。请求max_quote_age_seconds只能收紧，不能超过服务端900秒上限；这是当前Paper门禁上限，不是最终Live交易SLO。
- 缺失/过期报价、未来时间戳、非有限值或非正价格均阻止。不能用请求source_timestamp_valid=true覆盖服务端实际未来时间。
- Paper执行前，在重新计算账户资金/Kill-switch后重新执行ExecutionGate，阻止审批后已过期的行情。
- 已部分成交草稿的资金/持仓预估使用实际累计成交数量后的剩余比例；数量未知时保守减去已成交金额。原始委托总金额仍受单笔限额约束，当前草稿之外的批准订单仍计入预留。
- 保持原请求和响应路径兼容；服务端风险上下文新增_server_remaining_notional，用于审计剩余估值。无模型或数据库结构变更。

## 新增验收

五项报价测试覆盖：关闭报价检查+放宽时效仍不能放行缺失/过期/未来/零价；审批后报价过期不能产生Paper成交。

一项部分成交测试：10股×100的Paper单先成交4股，然后使可用现金仅够剩余6股并保留足够组合权益，第二次完成剩余6股。证明不会重复要求完整原单1000的资金，也没有减免剩余600的资金检查。

完整回归终态另记录在同名RESULTS JSON，测试环境为已有Python3.13虚拟环境、当前仓库源码、隔离内存SQLite。前端本轮未修改；原UI静态保留守卫、secret scan和diff --check通过。

## 范围限制

900秒上限只关闭当前可由请求任意放宽的入口，正式订单预览/提交仍需按市场与用途分别配置更严格的报价TTL；股票交易时段也需独立处理。

服务端持久化Quote仍未等同于外部可信供应商快照证明；来源资格、行情质量/序列缺口、资产制度、持仓时效、真实Broker快照、并发原子预留、审批版本/TTL和全部T1–T7目标仍需开发验收。当前测试不代表远程CI、外部Sandbox或实盘通过。
