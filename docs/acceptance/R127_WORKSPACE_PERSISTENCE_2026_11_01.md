# r127：工作区持久化、版本冲突与租户缓存修复

目标仍在进行。本轮新增工作区后端和原设置页同步入口，无实盘授权、无付费模型调用、无部署推送。

## 实现与API

- 新TerminalWorkspace表以(user_id,workspace_id)为复合主键，保存version、context_json、layout_json与创建/更新时间。迁移20261101_0023，前置20260717_0022；没有改写旧图表布局文件或浏览器笔记。
- GET /api/v2/workspaces/{workspace_id}读取当前主体私有记录；PUT携带expected_version及typed context/layout保存。初建预期0，已有记录以SQL版本条件更新；并发创建/旧版本写入返回409，事务同时写审计。账号引用检查实际归属，管理员工作区也不跨用户读取。
- context保存页面/频道、市场类别、标的、平台、周期、来源及可选账户/模式；layout当前仅研究侧栏开关和密度偏好。未知字段拒绝，不能保存Key或trade_enabled。响应execution_authorized始终false，工作区选择不能授予交易权限。
- 现有设置新增“工作区同步”：显式读取、保存、核对后恢复。冲突提示先读取最新快照，不自动覆盖。恢复当前支持页面/标准频道、标的、平台、周期、研究侧栏；未知平台/频道/周期、带账户/执行模式的记录会拒绝应用并保持当前工作区。股票专用且不在现有META标准列表中的频道恢复尚未支持，明确报错；不默默替换为其他频道。
- API/模型保存不包含客户端user_id或本地identity/version，服务器主体和资源版本各自负责。账户/模式恢复必须走后续专门授权流程。
- 全量回归暴露旧租户查询lambda默认参数缓存问题。改用model.user_id == current_tenant的绑定SQL条件，并增加同一查询a→b→a→b切换测试，避免旧租户过滤条件被复用。
