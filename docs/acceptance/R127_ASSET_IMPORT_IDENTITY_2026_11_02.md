# r127 行情/持仓导入资产身份（2026-11-02）

本增量修复按 symbol 复用资产和给同名持仓串价的问题。整体 113 项规划保持进行中，不表示来源身份注册表或真实券商已验收。

## 实现与文件

- `backend/app/services/asset_identity.py`：按 symbol、asset_type、market、venue、currency、chain_id、contract_address 查找。前五项去首尾空格并忽略大小写；链和合约保持精确字符串，不擅自合并跨链/大小写地址。支持有链、无合约的原生币；有合约时必须指定链。完全相同身份出现多个已有资产时，拒绝猜选第一条，要求先解决重复数据。
- `backend/app/services/data_sources.py`：报价、K 线和只读账户持仓使用该匹配。新资产默认交易能力全关；复用已有精确资产时保留其用户名称、链/合约和交易配置，只读账户同步不再全局改写这些字段。
- 同服务把导入价格按 asset_id 更新持仓估值。平台/币种/市场/类型不同的同名资产不会收到这次行情价格。报价和 K 线快照包含实际资产 ID 与作用域字段。
- 模拟资产元数据仅用于真正的 `mock_market_data` 连接；真实/自定义连接即使使用同名代码或将 quote.source 标成 mock，也不能套用模拟资产的市场/平台信息。
- `backend/app/adapters/types.py`、`backend/app/adapters/market_data_readonly.py`：报价/K 线结构新增可选 currency，Yahoo 解析其响应 meta.currency；若提供者返回的币种与请求不符，导入拒绝。返回的代码、K 线周期与请求不符同样拒绝，不将返回值写入另一标的。
- `backend/app/services/mock_import.py`：模拟导入和模拟报价刷新也使用精确资产查找；使用返回资产 ID 构造报价/估值，移除全表按代码覆盖的选择方式。
- `backend/app/api/mock.py`：重复身份冲突返回 422 并回滚待提交改动，提供可处理的错误而非 500。
- `backend/app/services/decision_gates.py`：研究门对市场 K 线快照成功导入的标的行也应用资产覆盖检查，原报价覆盖检查继续生效。

无前端源码或数据库表结构变更，无历史数据删除/重归属/自动启用交易，无实盘、模型调用或部署。

## 剩余限制

- 精确匹配与插入之间尚无数据库唯一约束/事务锁；并发首次导入仍可能产生重复身份，后续查找会拒绝歧义，但不等于已防止重复创建。需要保留数据的冲突审计、迁移与并发验收。
- 当前 venue/market/type 主要来自适配器调用的声明；未知平台仍以 provider 作为 venue，未宣称已经证明交易所真实上市标识。Yahoo 本轮仅新增响应币种核验；跨交易所别名、证券主数据与 instrument registry 仍待完成。
- 无币种元数据的提供者仍按声明币种工作；不能将请求字段本身当作提供者证明。可信目录与报告重验继续生效，但不替代完整来源认证。
- 保留全部旧资产、报价、K 线、持仓；不能凭此修复证明旧记录没有错绑，也不自动猜测历史身份或转移其财务数据。历史审计与显式迁移仍需独立完成。
- 同一精确资产的行情可以更新其持仓估值；这只是只读价格估值，不是成交/真实资金证明。真实券商同步状态与实盘执行仍不在本轮范围。
- 同一资产同周期/时间的 K 线继续使用原 upsert 语义；多来源版本存储与不可变历史证据契约未由本页完成。
- 其他 symbol-only 导入/前端候选查找、无强制报告的手动交易路径、完整 UI/所有任务验收继续按整体规划推进。
