# 03｜现有 UI 中的 Agent 原生交互（不新增一套替代页面）

## 1. 设计目标

让原本右侧的 Ace Agent 从“单一聊天 + 策略推荐”升级为贯穿所有工作区的**可信行动中枢**：Chat（问答）、Team（多 Agent 协作）、Tasks（运行任务）、Actions（待处理事项）四个互相关联的视图。保留现有浅色、可收起的右侧栏和图表布局，绝不以重做的黑色小看板替换现有专业页面。

### 三种使用心智

1. **Trade First**：专业交易员使用盘口、票据、快捷键进行手动交易；Ace Agent 只在需要时给出风险提醒。
2. **Ask First**：用户先在当前图表/资讯/持仓提问，Agent 基于上下文生成分析和可操作卡，用户再确认。
3. **Monitor First**：用户给 Agent 订阅监控目标，Agent 不断识别与报告异常，重要事件进入 Inbox；不每次手动触发模型。

## 2. 现有 Ace Agent 的四个面板（共享同一个状态）

| 视图 | 目的 | 必须包含的内容 | 必须具备的动作 |
|---|---|---|---|
| Chat | 最短路径提问 | 选定标的、交易所、周期、可选行情/新闻/持仓快照、消息、模型状态/成本 | 发问、选择资料、显示来源、复制引用、生成行动卡、打开资料 |
| Team | 专业 Agent 委员会 | Technical / Fundamental / News / Macro / On-chain / Bull / Bear / Risk / Portfolio / Execution Reviewer，每个真实任务状态 | 启动/取消任务、查看输入输出、展开证据、重试单个 Agent、比较异议 |
| Tasks | 长期工作流程 | 任务队列、运行中、失败、等待批准、结束状态、触发来源、预计成本/已花成本、超时 | 暂停/重试/查看详情、取消监控、前往相关页面 |
| Actions | 不打扰主屏的行动中心 | 风险警报、策略失效、订单异常、AI 提案、审批请求、来源故障 | 确认收到、忽略/稍后、跳转上下文、审查订单、暂停策略 |

### 实时任务卡状态

`QUEUED → RUNNING → WAITING_TOOL/WAITING_USER → COMPLETED / FAILED / CANCELLED / EXPIRED`。必须每个阶段有 `task_id`、启动时间、Agent/工具名、进度事件、引用快照、错误类别。不能靠前端 `setTimeout` 伪造“AI 正在研究”。

### Action Card 的四个等级

- **INFO**：简单解释/文章/研究摘要；可跳转，不能下单。
- **RECOMMENDATION**：提出风控/策略/关注建议；有证据与局限性。
- **ORDER_PROPOSAL**：结构化交易提案；账户、数量、市场、退出逻辑和风险预算仍由服务端验证；生成草稿不等于批准。
- **APPROVAL_REQUEST**：后端风控完成且授权策略/用户请求生成的待审项目，要求完整确认票据和过期重验；只能独立 `ApprovalService` 批准。

任何 Action Card 必须展示：来源对象、Agent/模型、时效、证据快照、置信度的定义（若存在）、风险提示、执行能力是否开放。禁止固定展示 90% 胜率、86% 成功率，除非明确回测样本/窗口、独立验证、方法与可靠统计区间。

## 3. 图表原位 Agent 交互（截图 S2）

- 图表工具栏现有“AI 解读”保留，新增 **选中区域 → 分析此区间**。右击选区/画线/指标，弹出“解释、与历史类比、对照资讯、创建提醒、生成研究报告”；绝不触发交易。
- K 线区间传递经过 schema 验证的 OHLCV 和 `{venue,symbol,timeframe,start,end,candle_utc_closed,data_snapshot_id}`，用户可预览/取消附带；CSV/Replay 资料明确标为用户数据或历史切片。
- 研究建议的支撑/阻力标记可选择性投到现有 Drawing Overlay，而不是自动改写用户画线；附 `annotation_id`, `source_task_id`, `evidence_id`, `created_by=agent`, `status=proposed/accepted/rejected`。
- 图表一键打开 `OrderTicket`，默认只预填方向与参考价；用户需主动指定账户/数量/模式。LIMIT/MARKET 与 TP/SL 后续按券商实际能力扩展。
- 订单/持仓变化底部面板实时刷新，但不能让 Agent 面板抢占主图；右栏可固定宽度、自动隐藏，保存布局。

## 4. 首页 S1：AI 智搜升级（避免空白却不强制变成密集看板）

- 保留首页大搜索/问答输入框、Web3/股票切换、已有卡片及顶部导航。用户可选“快速问答/深度多 Agent 研究/搜索市场与功能”。
- 在输入框附近增加轻量 `ConnectionStatus`：未配 AI Key/后端离线/市场数据缺失/当前标的。该区域是状态而非满屏统计。
- 空白区可开启个人化摘要模块（我的关注、进行中的研究、今日需处理事项），**默认简洁，可关闭，不新增过度卡片**。
- 深度研究跳转当前工作区的 Ace Agent/研究详情，继续任务不丢上下文。

## 5. 快讯/要闻 S3/S4：离线与影响研究

- 新闻失联：先显示明确错误类（网络/认证/API 配额/源站超时）、最近成功获取的源级缓存、精确获取时间、手动重试与配置入口；不能一直空白显示“正在读取”。
- 浏览资讯可点“询问 Agent”：自动带 `news_item_id`, `publisher`, `published_at`, `fetched_at`, `original_url`, `content_hash`；推断影响要标注“可能关联”。
- 关联当前持仓/监控策略需由证券 ID 匹配器和引用依据支撑；不把关键词命中直接渲染成真实市场影响。
- 重要资讯通知应去重、按来源/用户设置过滤，避免大量弹窗刷屏。

## 6. 我的策略 S5：从笔记走向完整实盘策略

- 保留九大策略分类、三栏笔记编辑器、标签与关联图、现有本地笔记兼容。先构建无损迁移工具，迁移后仍可导出本地数据。
- “AI 分析笔记”输出 `ThesisDraft / StrategySpecDraft`：目标标的、时间周期、信号、反例、风险、退出条件、数据来源与待用户补充字段；不允许固定模板作为已执行分析。
- “生成策略草稿”只创建 `strategy_version`，不自动启动；`Backtest → Paper → Live approval` 三阶段需看到实际数据、历史绩效、模拟成交与风险。
- 图表脚本运行有配额/沙箱/暂停，存储与版本可回滚，策略信号和真实订单可回溯至策略版本、信号 ID、行情快照 ID。

## 7. 交易和持仓的 UI（尽量复用现有弹层/底部工具栏）

### 下单票据要求

账户、可用余额、资产类别、交易所、精确合约或现货品种、买卖方向、订单类型、数量/单位、价格、预计手续费、预估价格影响、真实模式、净仓位影响、风险预览、订单有效期、确认信息及提交反馈。

- 任何与账户相关字段必须由后端读取并版本化；用户输入数量、价格不等于实际报价/敞口。
- 实盘确认必须显示 `LIVE + 交易所 + 账户别名 + 可能损失 + 提交方式`；按钮非默认聚焦，必要时二次确认。
- “提交已请求”≠“交易所受理”≠“成交”；在交易所回应未知时单独显示 `UNKNOWN_PENDING_RECONCILIATION` 并禁止自动重试同一交易。

### 底部交易抽屉

现有底部脚本与交易区域保留，添加可调的 Orders / Fills / Positions / Alerts / Agent Tasks。支持压缩为状态栏；行点击打开订单详情，并与图表选中标的联动。

## 8. 系统快捷方式（非破坏式）

- `Cmd/Ctrl+K`：跨页面搜索标的、命令和自然语言指令。
- `Cmd/Ctrl+Enter`：在确认票据中提交 **预览/校验**，不直接发送实盘。
- `Esc`：关闭非关键弹层；真实交易审批对话框关闭不代表撤销订单。
- 页面右键菜单与键盘无障碍等价，所有 IconButton 有 aria-label、focus visible、足够点击区域。

## 9. 每个 UI 动作的统一响应

`USER_INTENT → LOCAL_PREVIEW → SERVER_VALIDATION → (IF NEEDED APPROVAL) → CONFIRMED_ACTION → SERVER_EVENT → UI_STATE_REFRESH`。

任何按钮的验收不只是有 onClick，而是：正确写入/读取真实服务 → 权限错误可见 → 超时/取消/重试定义清楚 → 刷新后状态可恢复 → 不触发越权或误下单。
