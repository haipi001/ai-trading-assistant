# 00｜产品定位与不可妥协的约束（长期产品宪章）

## 1. 定位

**AI Trading OS — Agent-Native Professional Trading Terminal**。长期愿景为“Agent 的彭博”：让专业市场、研究、交易和风险工作台与随时可用的多 Agent 协作体系融合。这里“彭博”是专业工作流、信息密度、检索效率、跨市场联系的对标，不等于照搬 Bloomberg 界面或承诺有其专有数据。

**价值主张：一个研究结论能走进实际交易，一个实际订单能回溯到证据，一个持仓变化能被 Agent 及时理解。**

非目标：炒作式预测、保证收益、黑箱无限制交易、HFT 交易所撮合级系统、早期重做企业级 OMS、Kubernetes、为了技术炫技新增几十个孤岛式页面。

## 2. 用户画像与关键任务

- **专业自主交易者**：快速行情/图表、盘口、下单、订单生命周期、快捷键、风控、稳定性；可关闭 AI。
- **AI 增强型交易者**：图表选区 → Agent 研究 → Evidence → 交易提案 → 执行确认 → 订单 → 复盘；低摩擦且透明。
- **策略与量化研究者**：数据源、代码策略、回测、Walk-forward、Paper、实盘转化、运行监控；允许高级能力，但不覆盖简单交易路径。
- **跨市场投资者**：股票/ETF/CEX/Web3 的单一视角，但不同资产的交易制度、账户和风险语义不能混淆。

## 3. 六个产品支柱

1. **Professional Terminal**：无 Agent 也有完整的专业行情、订单与组合管理能力。
2. **Agent Native**：观察/研究/交易监督三类 Agent 与实时上下文融为一体，而非另外打开聊天应用。
3. **One Source of Truth**：行情快照、账户/持仓、草稿、成交、风险与 Agent 行动共享可追溯 ID。
4. **Trust & Precision**：真实/演示、收到时间/交易所时间、订单提交/成交、预测/事实必须清晰分隔。
5. **Progressive Disclosure**：专业功能不删除，但提供常用、专业、研究三类工具视图及配置工作区。
6. **Safe Real Trading**：支持真实交易；由真实交易适配器、身份认证、确定性风控、用户/策略授权、幂等与对账保护。

## 4. 三种模式、两种控制轴

- 数据与执行模式：DEMO / PAPER / LIVE。顶栏、票据、订单卡、持仓、Agent 提示必须一致展示。
- AI 自动化模式：A0 READ_ONLY、A1 RESEARCH、A3 DRAFT、A4 HUMAN_APPROVAL_LIVE、A5 SCOPED_AUTO；不实现无限权限的 A6。一个模型选择不能自动提升权限。
- 手动/Agent 切换不改变底层交易权限。自定义策略也不能绕过风险引擎。**用户手动交易必须能独立使用，不强制先打开对话框**。对人类主动下单允许“简明交易理由”，不强求多 Agent 研究完成；风控规则仍统一生效。

## 5. 新开发的评价指标（目标而非已测成效）

- 100% 原有导航入口、子页面、图表功能及策略类别可到达；关键控件有可执行动作、错误状态或明确不可用说明。
- 一次典型手动限价单：从行情页面到打开完整下单确认票据，目标交互 ≤3 步；快捷键可更快。
- 订单提交后的反馈以交易所返回为准；当未知状态发生时显示“待核实”并查询，不显示虚构成交。
- 通用市场与订单状态在页面切换后保留；不同市场、账户、交易模式不得相互污染。
- Agent 在图表、资讯、策略、持仓、订单的“当前对象”上都可立即发起研究，并展示任务进度、快照与证据。
- 加入真实监控：错误率、用户工作流完成率、Agent 调用成本、风控阻止原因、订单对账延迟；先采集真实基线，再设 SLO。

## 6. 核心用户工作流

1. 开盘/启动：识别真正在线的行情、账户状态、待审核订单、Agent Briefing；离线明确降级。
2. 市场：全局搜索 → 标的 → 图表/盘口/新闻 → 画线/筛选 → AI 研究或手动交易。
3. 策略：策略目录 → 编辑/指标脚本 → 回测 → Paper → 确认监控 → 实盘授权。
4. 交易：票据 → 预览费用/仓位影响/风险 → 明确账户/模式 → 提交 → 确认/失败/部分成交 → 撤单/改单 → 对账。
5. Agent：选中对象 → 一键研究 → 分工/过程/证据 → Action Card → 草稿（不直接下单）→ 关联交易及复盘。
6. 复盘：已实现 PnL/费用 → 策略假设与实际轨迹 → Agent 归因建议 → 人工决定是否更新 Playbook。

## 7. 核心守则

- 先保留、后改善；不因“简洁”减少专业能力。
- 先观察运行中软件如何使用，再拆分巨型组件；不要盲目拆成百个空组件。
- 所有数值必须区分真实、计算、模型估计、示例；模拟策略胜率不能展示为真实收益率。
- 无 API/数据/账户权限时，展示明确的原位指引、重试与降级，不为空白界面伪装正常。
- 如果某条产品需求与安全约束冲突，以真实交易可控与准确展示优先。
