## 分阶段的跨界面交付

### T0：先为真实交易准备安全与可发布性

- `.github/workflows/ci.yml` 目前缺少 `[mcp]` extra；修复并让 pytest 完整执行，而不止通过 collect。
- 生产 `MANAGED_AUTH_REQUIRED=true` 必须与真实身份服务、Cookie/CSRF、CORS、API rate-limit 和跨用户测试一起工作；不是简单改布尔值。
- 当前 `/decision-gates/evaluate` 的外部输入需要可信归属；做服务器端账户/风控数据重算，增加授权和绕过测试。
- 建立所有主导航和五张截图的视觉回归测试；迁移记录、运行环境、可用功能 vs fixture 清单。

### T1：最先让用户明显感觉“下一代 Agent”，又不破坏图表

- 共享 WorkspaceContext 和通用 Drawer/Modal 状态，不改变屏幕布局。
- Ace Agent 显示当前上下文、来源、任务状态；首页大搜索升级统一 Agent 查询入口。
- 资讯获取失败不再空白/无限加载；真实/演示行情状态必须全站一致。
- 从策略笔记、图表、资讯、一笔持仓都能快捷分析当前对象；目前可先用既有真实 BYOK 聊天，不宣传已完成多 Agent。

### T2：真正能手动交易

- 订单网关、交易所真实账户与专用交易 Key（只读连接不得自动获得交易权限）。
- `OrderTicket + RiskPreview + Approval` 复用图表/底部 UI；每次有正确的账户、数量和实际费用/风险说明。
- 私有订单事件/轮询与对账；Unknown 状态持续直到交易所确认。
- 先只做 1 venue spot，禁止合约杠杆；后续再扩增。

### T3：真正多 Agent

- 从现有 mock 研究委员会迁移真实 Provider 并启用状态持久化与证据；优先 2–4 个角色而不是全部并发。
- 研究结果通过行动卡直接联动现有图表与订单草稿；模型不能直接调用交易适配器。
- Agent Inbox 只显示相关异常，支持预算、静默时段、去重与回溯。

### T4/T5/T6：持续专业深化

- 策略监控和回测/实盘一致性优先于新策略种类；展示绩效真实样本来源。
- 股票独立交易制度/市场日历/货币与账户规则，不用 CEX 精度规则套股票。
- 自动交易只能通过受限策略授权，策略与 Agent 调度器均需支持 Kill-switch、过期/撤销与防重复下单。

## 不要做的事情

- 不要新建另一套简陋 Dashboard 取代 r127；不要一边重做 UI 一边删除原始工具栏/页面。
- 不要一开始把 Hummingbot/LEAN/Freqtrade/Nautilus 的完整引擎同时加进主进程。
- 不要把全部 LLM 回复强迫进 TradingAgent 委员会；短问答应使用轻量快速路径。
- 不要为了进度假造实时订单、真实账户、90% 策略胜率或终端成功状态。
- 不要在仅有单元测试/夹具时打开生产实盘；必须真实交易所回报和风险演练。
