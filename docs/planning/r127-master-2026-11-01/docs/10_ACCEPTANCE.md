# 10｜完整验收标准：100% UI 保真、可用功能、Agent 与真实执行

## 一、三层验收，不得相互替代

1. **静态/组件/模型测试**：逻辑正确，控件有回调、schema 通过，不意味着后端和外部交易已运行。
2. **隔离端到端测试**：UI↔API↔DB↔模拟 Broker / Agent Provider，包含 HTTP、重登、重连、失败流程；说明是 fixture。
3. **外部真实端到端测试**：真实有权限的 API 账户、外部 API 受理/成交/查询/对账和可恢复，需用户授权且脱敏证据；模型真实账户调用要注明 Token/费用；不可用时明确留“未验证”。

## 二、五张用户截图的固定体验锚点

- **S1 首页**：顶栏、Web3/股票、AI 智搜区域、频道、侧栏与底部状态保持；从 AI 输入框到真实模型配置/提示/任务无假成功。
- **S2 行情**：与提供截图对齐位置：左导航、上方行情导航与图表工具、多图表/指标/画线/脚本/回放、右侧 Ace Agent、底部操作区。新增 Agent Dock 后主图仍可缩放/切换/交易。
- **S3 快讯**：频道、列表、右侧来源信息可见；断网或未配置 API 时可见状态、缓存和重试；不无限假加载。
- **S4 要闻**：频道、两栏阅读布局、媒体来源、右侧文章详情不退化；点击单篇进入 Agent 后可返回原位置。
- **S5 我的策略**：九大策略分类、笔记列表、标签、编辑器、AI分析、生成策略入口以及笔记关系能力全部保留。

每次 PR 自动生成截图比对/语义路径测试。允许合理改善间距/响应式/无障碍，但偏离截图需要说明“为什么更好、功能未丢”。截图不作为金融功能正确性证明。

## 四、真实交易门禁（全部满足才开放）

- 公网入口开启真正会话认证，多用户隔离、CSRF/CORS、角色权限、审计与密钥存储验证；所有用户/策略不可能自行提升权限。
- 风控使用数据库+实时账户读数；手动字段不能绕过硬限制；报价/持仓/订单状态时效有清晰策略。
- 交易 API 的最小下单权限、无提现/转账权限、IP allowlist（供应商支持时）、账户权限可检查。
- 订单提交能防重复、支持未知状态与对账、部分成交/撤单竞态、费用归集和资金/持仓一致性。
- 用户可明确确认 LIVE 账户与具体订单，并且后台 Kill-switch 在真实下单入口生效；默认关闭自动策略。
- Sandbox/模拟交易通过全套失败注入；真正小额订单需用户主动同意与在实际交易所明确的真实证明；任何验收包都不得包含 API Key。
- 失败告警触达操作界面，关键异常不会被吞；生产部署可回滚、审计可导出、数据库有恢复演练。

## 五、Agent 验收

- BYOK/平台模型状态与费用策略真实，调用前展示资料范围、调用后来源引用准确；无授权/无 Key/无额度则阻止而不是合成虚假完成。
- 多 Agent 每个角色都有运行状态、真实工具证据、输入输出 Schema；容忍某角色错误、能够取消/恢复任务并保留已产生证据。
- Agent ActionCard 能从策略/图表/新闻/持仓点回源页面；提案不会直接交易。
- 任意来自新闻/网页/笔记的 prompt injection 不可扩展工具授权；Agent 输出中指令不影响账户实际权限。
- Token/美元预算和异常频率限制有效；后台监控不能因为前端关闭产生无限调用/重复下单。

## 六、质量与工程门禁

- GitHub Actions 后端 pytest 全量成功、迁移 guard、前端 models+interaction、生产构建、依赖安全扫描、凭证扫描、API contract 与 Playwright E2E（新增）。
- 新增 UI/Agent/live API 必须补正向、权限拒绝、超时、并发、断线、跨模式、跨用户和状态恢复用例。
- 所有 UI 主要动作都需有真实业务效果或明确“功能暂不可用”的可信说明；有 `onClick` 不构成功能验收。
- `VERSION.md` 更新仅写已验证事实；每个任务留 CI 链接、commit、脱敏截图/录像及外部调用有无发生的说明。
