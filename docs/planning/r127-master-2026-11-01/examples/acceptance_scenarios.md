# 端到端故事与失败注入（用于真实 Playwright 和 pytest）

- **Scenario 01 / S1 首页搜索**：打开 r127 首页，Web3→股票切换；搜索标的，跳行情；后端失联或 AI 未配置时显示可见错误，不虚构研究报告。
- **Scenario 02 / S2 图表到 Agent**：BTC/USDT OKX 1h 选中 60 根真实已收盘 K 线→Ace 研究预览→发送；切 ETH/USDT 5m 后旧材料必须清除或明确标为历史快照；Agent 返回可点回市场来源的证据。
- **Scenario 03 / S3&S4 新闻源**：网络断开，某媒体 RSS 超时，快讯/要闻仍展示最后成功内容并标注过期/错误；某一来源恢复时不清除其他来源；AI 引用需要实际文章 ID。
- **Scenario 04 / S5 策略闭环**：保留原笔记/标签/关系→生成结构化 draft→回测→Paper 执行→交易记录→用户复盘；过程中不能把模型模板当真实回测。
- **Scenario 05 / CEX MANUAL LIVE**：在用户授权的独立真实账户，以最低合理金额限价单创建→风控预览→人工确认→交易所订单确认→查询/部分成交/撤单→对账；失败时保持 Unknown 而非认为失败后重复下单。此故事绝不能用假服务结果标注“真实完成”。
- **Scenario 06 / 手动和 Agent 不冲突**：不打开 Ace 也可以完整下单；Agent 提案输入的订单草稿用户修改数量后，旧风控/批准自动失效。
- **Scenario 07 / 掉线重连**：断开浏览器 SSE/断交易所私有流/Redis 重启→重新连接→用游标/快照恢复状态；任何 order_id 不重复账本。
- **Scenario 08 / 同时操作**：同一账户两个浏览器窗口重复点击提交；唯一 idempotency 记录、不双单，显示相同订单 ID。
- **Scenario 09 / 安全**：无登录、错角色、跨租户、AI prompt injection、冻结账户、提现权限 Key 均无法做 LIVE 订单。
- **Scenario 10 / 截图保真**：S1/S2/S3/S4/S5 的主要布局和交互全保留，Agent 展开关闭、窗口缩放、滚动、图表多窗口、策略脚本不回归。

所有场景记录三类证据：自动测试、真实浏览器操作、外部 provider/broker 实际调用。没有外部授权时仅记录前两类，不得标已实盘。
